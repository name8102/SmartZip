# CLI 交互完善：密码、编码预览与结果反馈

> 状态：部分实施，2026-09-05。用户追加的短命令/别名已实现；密码与编码交互仍为设计草案。

## 用户目标

用户希望先了解项目最新状态，再进一步完善 CLI 设计；本轮明确优先“交互体验、密码与编码”。

追加要求：encoding-preview 太长，需要更短的命令和常用短别名。主命令采用 enc，旧名称保留兼容；extract/list/detect/test/compress/password/history 分别增加 x/l/d/t/c/pw/hist。

面向处理网络下载归档的普通 CLI 用户：一次命令能够完成密码补充、乱码判断和解压，遇到问题时知道当前停在哪里、可以怎样继续，并能在下次处理相同文件时复用已经确认的信息。

面向实现者：读完设计即可按 implement.md 的切片实现并验收，不需要重新决定提示含义、记忆规则或非终端行为。

## 必须延续的约束

1. 保留 detect / list / extract 的用途和共享引擎；detect 不求密码、不确认编码、不解压。
2. CLI 用逐行提示和数字/字母选择，不引入 TUI；复杂编码工作台继续留给 GUI。
3. 密码默认在可靠验证成功后自动保存到本地 SQLite，并支持关闭；不新增每个密码的保存确认步骤。
4. 密码候选优先保留显式输入、精确文件记忆、批次记忆，再使用其余候选；不引入新的密码破解后端。
5. 自动猜测编码不得写成 confirmed_encoding；list 不更新 last_extract_at；已确认编码按文件指纹复用。
6. CLI 负责输入与展示；验证、编码判断、历史落库与 staging 仍在所属服务/engine 中。

## 范围与优先级

| 优先级 | 用户可感知结果 |
| --- | --- |
| P0 | 密码输入不回显且不改变空白字符；中文/emoji 密码不会使列表崩溃；普通 ZIP 列表成功不再误记密码有效 |
| P1 | 密码输错后可继续输入，Enter 跳过当前归档，Ctrl-C 取消批次；成功保存或仅本次使用有反馈 |
| P1 | 编码候选展示同一批真实文件名；选中后复列并持久化显式选择；extract 与 list 复用选择流程 |
| P1 | 终端提示规则统一，批量操作不混淆当前归档与整个任务；输出冲突有默认操作和本批次策略 |
| P2 | 帮助、全局参数位置、dry-run、JSON 边界一致；password/history 按需初始化依赖 |

## 非目标

- 除用户追加的命名/别名改动外，密码与编码交互功能留待后续切片；不把整体设计标成已交付。
- 不重写后端路由、数据库历史模型，不移植 GUI，不新建 graph/scheduler crate。
- 不在本任务实现 test/compress；test 的损坏定位仍归原拆分任务。
- 不增加 detect/list 多输入、默认命令、配置编辑器、命名密码表、JSONL 事件流。
- 不在交互迭代中直接重编号退出码或替换既有 JSON schema。

## 交互功能验收（均待实现）

- [ ] 密码从提示、`-p`、stdin、剪贴板和导入到候选比较使用一致的内容保真规则，既有空白归一化测试相应调整。
- [ ] 输错两次后第三次正确仍能完成；跳过当前归档后继续批次；Ctrl-C 取消并完成清理和历史收尾。
- [ ] 普通未加密 ZIP 或仅文件内容加密 ZIP 的 list 不产生虚假的密码命中、统计和 known_files.password_id。
- [ ] 无需密码的 list 不提示密码；只有确实需要密码的阶段才显示候选尝试和输入提示。
- [ ] 默认成功保存只提示结果；`--no-save-password` 不落密码及其关联信息，同时仍能在当前批次内复用。
- [ ] 多字节密码列表不会 panic；普通日志、路由事件、历史事件不含密码明文。
- [ ] `list --pick-encoding` 与 `extract --pick-encoding` 显示可比较文件名、支持重选，并使用最终显式选择完成操作。
- [ ] 仅显式确认的编码被记忆；自动接受、非终端回退、预览、失败选择不覆盖旧 confirmed_encoding。
- [ ] 编码选择限当前文件；嵌套归档重新判断，不把根文件交互选择扩散到其他归档。
- [ ] 终端/重定向/JSON/stdin 密码输入矩阵符合 design.md；没有静默忽略的显式选项。
- [ ] 输出提示与进度串行；冲突默认跳过，批次策略限对应问题类型；最终摘要列真实输出路径与跳过原因。
- [ ] CLI 参数在业务初始化前校验；password/history 不依赖后端配置可用性；dry-run 无 DB、后端、解压副作用。

设计稿交付通过源码核对、隔离 CLI 复现、现有相关测试和文档链接检查验收；以上功能清单用于后续实施，不以本轮测试通过代替。
