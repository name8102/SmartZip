# 新版任务系统实施记录

设计与验收依据：`docs/task-system.md`。

## 已完成

- `TaskId`、`NodeId`、`AttemptId`、`DecisionId` 使用随机 UUID。任务提交时一次创建任务和根节点，节点的阶段、generation、父子和根身份写入现有历史库。
- `StateStore` 用独立线程独占执行状态连接；节点状态变化与阶段事件在同一事务写入。执行节点本身就是唯一的文件历史行，不再另外追加一份完成记录。
- `TaskCoordinator` 在进程内共享，按 High/Normal/Background 权重和任务内根轮转派发。CPU、后端进程、文件系统设备 I/O、读写路径在一次准入中取得和释放；等待输入会释放阶段租约。
- 多根解压可以并行推进；`on_error=stop` 会取消同一任务的其他根。密码、编码、内嵌选择和输出冲突成为带 `DecisionId + generation` 的持久等待，答复后重新竞争资源；同一节点仍只允许一个写 staging 的密码尝试。
- `OutputMaterializer` 拆成暂存、布局/冲突计划和提交。提交前保存 commit ID、源对象身份、目标、标记、备份、实际输出用量及成功去重/密码/编码事实；发布后立即写发布事实。重启可以补记已经完成的 rename、恢复成功事实和发现子归档，或清理未发布 staging 并递增 generation 重试；证据不一致时明确失败。
- 提交给执行系统的是策略应用后的绝对输入/输出和实际资源请求。任务级输出文件数、字节数和嵌套候选数随事务持久化，恢复后继续累计；候选上限会记录明确原因并停止任务。
- 暂存目录以精确路径记录所有权；Linux 外部后端设置父进程死亡信号，恢复清理前不会留下仍在写暂存目录的后端。覆盖提交会重新校验用户确认时的目标版本，发布完成后的取消保留成功结果。
- owner lock 阻止两个进程恢复同一状态库。CLI 和 GUI 在下一次解压入口恢复未完成任务；持久快照移除手工和剪贴板密码，只恢复非秘密策略。
- GUI 会提交当前拖动后的队列位置，并让同一进程的解压批次共用协调器。恢复任务与当前请求并发驱动，一个恢复任务等待输入不会阻塞其他任务；暂停状态跨重启保留。停止任务不会终结带提交意图的节点，保留它给下次对账。

## 验证

- 必要的新测试覆盖原子资源准入与公平、等待输入释放资源、任务级停止、停止时精确收尾正在等待的内嵌节点和正在扫描的根节点、generation/暂停/预算恢复、提交后崩溃对账与成功事实、提交意图在停止时保留、执行行与历史行唯一性，以及暂存/目标替换安全。
- `cargo test -p smartzip-archive -p smartzip-db -p smartzip-engine -p smartzip-cli -p smartzip-gui --no-fail-fast` 通过：archive 77 项通过、1 项仅供父进程死亡测试调用的 helper ignored；db 48 项、engine 219 项及集成测试、CLI 和 GUI 测试全部通过。真实 7zz GUI 验收中原有的 5 项 ignored 测试未自动执行。
- 独立 Astra 审查在修复七轮发现的问题后明确通过；最终轮复核了运行中扫描的任务级错误停止收尾，并独立执行 `cargo test -p smartzip-engine --lib stop_on_error_` 和 `git diff --check`，未发现新的 P0/P1/P2 问题。

## 保留边界

- 扫描器没有跨重启解析续点，恢复会从阶段头重做。
- 调度器当前没有进程级临时空间预约和内存估算；实际输出上限、空闲空间和取消仍由 `budget.rs` 在写入期间监测。
- 非 Unix 平台缺少可由标准库取得的稳定文件对象身份，因此不自动把崩溃窗口中的目标认定为本次提交。
- 预览配额、自适应并发和真实混合负载性能结论尚未完成，不能由单元测试推断。
