# 目标文件系统路径兼容性修复

状态：2026-10-02 已实施，验证结果及支持边界见 [implement.md](implement.md)。原设计日期 2026-09-22，源码基线 `f3b74a005856a23671f06f4eccc6ada2a62c0631`。

## 目标

归档成员在目标卷上遇到名称长度、非法名称、大小写或 Unicode 等价冲突时，生成确定性的目标路径并完整解压；所有结果仍经过现有暂存、布局、冲突决策、提交和恢复流程。区分名称分量限制、完整路径/API 限制和后端能力不足。

默认尽量保留目标卷允许的名称，另提供跨平台命名模式。目录改名必须一致作用于全部子成员；最终整理生成的名称同样受约束。危险路径不通过“清洗”变成可接受输入。

## 范围

- Linux/Btrfs、macOS/APFS、Windows/NTFS 的命名、碰撞与路径访问策略；未知卷明确记录探测置信度。
- 7-Zip 的精确选择、排除和单成员 stdout 通路；按索引读取 ZIP 的补充路径；Unrar 按已验证能力分阶段接入。
- 与现有资源预算、取消、编码、密码、布局、历史及提交恢复集成。
- 2026-10-02 交付包含提取、布局、恢复及 GUI 的完整接入；三平台原生验收状态和后端支持矩阵见实施记录，不包含压缩创建产品入口。

## 验收依据

1. 普通归档保留批量后端路径；需要映射的成员不能再由后端按原名创建。
2. 相同输入、编码、策略版本及目标语义得到相同内部映射；不受成员枚举顺序和临时目录随机名影响。
3. 名称不同但目标等价、清洗后同名、文件/目录冲突、重复归档条目均有明确处理；无静默覆盖或遗漏。
4. 7-Zip 混合路径的普通集合和映射集合互斥且完整，长目录的全部后代进入映射集合；stdout 必须唯一对应成员。
5. 所有写入、布局改名、冲突后缀、提交、回滚和清理遵守目标策略。完整深路径支持还须覆盖预算遍历和递归输入读取。
6. 失败后旧输出和源归档保持安全；取消先回收内容生产者，再清理暂存；不持久化密码。
7. 成功的路径变更可追溯，未支持的格式/后端清楚失败，测试报告区分规则测试、真实后端验证和原生文件系统验收。
