# SmartZip GUI 设计规格

日期：2026-09-12。状态：设计交付，原生实现待按切片验证。源码功能证据统一见 [core-audit.md](core-audit.md)，依赖证据见 [gpui-component.md](gpui-component.md)，配置字段定义以 [统一配置](../../../docs/configuration.md) 为准。

## 1. 产品边界与决定

采用**一个应用、一个任务队列、两个窗口**。快速窗口是随手投递和处理当前任务的入口；详细窗口管理同一批任务。切换、关闭或重新打开任一窗口不复制任务、不重新执行、不丢失交互请求。

当前 `smartzip-gui/src/main.rs` 只有拖放后 `detect`，不包含解压、配置、历史或调度。其 `cx.spawn` 内直接调用同步检测不能据此认定已迁出 UI 线程。历史 GPUI 验证报告只作为 API 线索，本设计不沿用其中“控件和跨平台已经全部验证”的推断。

默认保持核心策略：递归、密码顺序、输出布局、内层归档清理和状态读写都由统一配置决定。小窗口减少可见选项，不另设一组行为默认值。GUI 不调用 CLI 子进程来模拟核心集成，也不复制 engine 的扫描、密码尝试和材质化逻辑。

用户允许升级依赖。首选固定 `gpui-kit / gpui-component 0.6.1 + gpui-pre 0.3.1` 整体迁移，经原生 PoC 再接入业务。采用新版 DataTable、Tree、支持不确定态的 Progress 和遮罩输入，替换旧 `macos-blade` 平台配置；旧 0.5.1 组合仅作有证据的回退。通用控件覆盖需求，应用调度和归档业务仍需自建，具体版本证据及门槛见组件调查。

完整覆盖包含底层已有的压缩能力；它目前缺少 engine 工作流，列为必须单独接通的交付项。首个解压切片可以先运行，但不得以“GUI 全功能完成”发布。归档条目预览属于本次范围；选择性解压、直接预览文件内容、断点续传和运行中暂停没有现成契约，不做可点击的空承诺。

## 2. 视觉与窗口体系

| 项目 | 快速窗口 | 详细窗口 |
| --- | --- | --- |
| 初始尺寸（逻辑像素） | 400 × 540；最小 360 × 480 | 1180 × 780；最小 900 × 600 |
| 结构 | 原生标题栏、状态、投递区、当前任务、快速设置、管理入口 | 原生标题栏、176 宽导航、工具栏、主列表、可收合详情栏 |
| 内容密度 | 14px 正文，单个主操作，少量常驻信息 | 13–14px 正文，40px 表格行；路径可展开/复制 |
| 颜色 | 系统浅/深主题，单一蓝色主操作；警告同时有文字 | 同左，状态不只靠颜色区分 |
| 窗口行为 | 可记住位置；置顶为用户可选项，不自动抢焦点 | 记住尺寸和列宽；详情栏窄屏转抽屉 |

页面留白为 16/24px，控件间隔为 8/12px。系统字体支持中文，数字列等宽对齐；长路径省略中间段，选中后展示完整路径。百分比只对应确有数值的当前操作。可交互稿是视觉和流程参照，原生采用 gpui-component 主题 token，不模拟网页浏览器布局。

导航固定为“任务、历史记录、密码、归档预览、设置”。“检测”“完整性校验”“新建压缩”位于任务的新建操作菜单，当前任务的只读结果也能在详情打开。“后端诊断”放在设置，不占一整块常驻仪表盘。

## 3. 快速窗口

从上到下：标题与“打开详细界面”；队列摘要“正在运行 1 · 等待 2 · 待处理 1”；拖放区；当前任务；快速设置；最近结果。

### 投递与启动

1. 文件进入时高亮投递区，显示“松开后加入解压队列”；同时提供“选择文件”以支持键盘操作。不信任后缀，伪装文件也送入核心检测流程。
2. 一次投递创建一个批次任务，保留多输入请求和批次内密码复用语义。任务详情展开各根输入及动态产生的内层候选；队列排序以批次为单位。不得为方便表格行而把每个文件悄悄拆成独立工作流。
3. 默认投递后自动排队启动。投递区下方始终展示本次目标规则和配置摘要；队列暂停时只入队。用户可在 GUI 偏好关闭自动开始，改成确认输入后“开始解压”。
4. 默认输出为**本批次首个输入的父目录**，与核心一致。多目录投递时展示解析后的实际输出路径，不笼统写“原文件位置”。需要不同输出目录时，用户分别建任务或显式指定本批次目标。
5. 同一路径/分卷组重复投递且正在队列中时，提示已有任务并允许明确“另建任务”；分卷入口和有效成员由已有 VolumeSet 能力解析，不能自行仅按文件名后缀合并。目录投递先进入输入审查，不自动假定是解压或压缩；解释其用途并让用户选择归档文件或新建压缩。

### 快速配置

常驻字段为输出目录、递归开关、布局选择和“更多”。每项显示当前有效值，不在界面打开时写回配置。更多弹层含递归深度、编码、冲突处理、手动密码和本次历史开关；其余转到详细设置的对应分类，保留正在编辑的草稿。

修改默认作用域为“下一次投递”，入队时冻结快照；已排队任务需在任务详情显式修改并重新校验，运行任务不能变更。用户点“保存为默认”才调用配置文件安全写入；明确展示文件路径及改变的字段。手动密码永不写入 TOML、草稿持久化或任务配置快照。

### 当前任务与结果

- 运行时显示文件名、当前阶段、当前操作的真实百分比（若提供）、已发现/已处理归档数量和“取消”。递归还在发现子任务时不显示批次总百分比、固定剩余时间或虚构速率。
- 没有可信百分比时用忙碌指示和阶段文字；取消后显示“正在停止并清理”，直到后端回收、清理和结果返回，不立即显示成功/已取消。
- 有多个任务时显示当前关注项和其余数量，点击摘要打开同一队列。待输入任务显示持久“需要密码/需要确认”卡片，选择后在小窗口即可完成四类交互。
- 完成后显示成功、部分完成、失败或取消，带输出入口和失败项数量；“查看输出”只对已提交且仍存在的路径启用，“重试”创建新任务。没有文件或未识别归档时显示原因，不吞掉 I/O 错误。

## 4. 详细窗口

### 任务与调度

工具栏：添加文件、新建操作、暂停/继续队列、最大并行任务数。默认并行数 1；设置为大于 1 前必须通过资源与数据库并发验收。队列暂停只停止启动新任务，不冻结后端或等待输入的任务。

任务列表列为名称/输入数、操作、状态、当前阶段、输出位置；提供“全部、执行中、排队、待处理、已结束”过滤。支持选中、批量取消排队项、排队项上移/下移/移到最前。排序只改变未开始任务；不对运行任务承诺优先级抢占。默认同优先级 FIFO。

详情包含“概览、文件、事件、配置”。概览显示当前操作、输入、目标、实际后端、可执行动作；文件按父子关系增量呈现递归候选和输出，历史没有完整父子证据时退回平面文件列表，不能编造树。事件默认摘要，展开路由可看候选排除、尝试和 fallback；不创建另一条 router 日志通道。

调度与资源契约：

- 每个批次保留独立取消令牌、事件作用域、配置快照与密码候选缓存，跨任务不共享临时明文密码。
- 先实施单并发队列，再启用有上限的并发。不同任务的输出根相同或互为祖先时串行；输入位于另一个任务输出/清理范围时同样等待，未知路径别名采用保守串行。最终碰撞仍交由核心在布局后处理。
- 等待用户决定的任务仍持有它的执行名额与输出租约，避免无限堆积暂存文件；因此单并发时后续任务会等待，界面明确显示原因。不要为了“后台继续”无上限释放名额。
- 并行数降低只影响后续启动，不终止已运行任务。每任务预算继续生效；同盘预算不能按每任务剩余空间各算各的，需调度器额外协调预留上限和磁盘余量。无法提供协调时并发保持 1。
- 窗口关闭不取消任务。关闭最后窗口且仍有工作时，在没有验证托盘/后台生命周期之前提供“继续工作并保留窗口”与“取消任务并退出”；退出必须等待后端回收和清理。显式退出不会因隐藏窗口而偷偷继续运行。
- 第一版队列只在当前进程存活；重启不自动恢复暂存树、不把历史记录当恢复点。若以后持久化待执行队列，只存不含凭据的请求，恢复时重新校验源文件并由用户重新开始；非本次完成条件。

### 历史记录

提供任务历史与文件历史两个视图，按日期、操作、状态、路径筛选，分页/分段加载。详情复用结果展示：任务终态、每文件动作、编码、输出位置、密码引用、配置快照、事件及 test 报告。旧记录缺少字段显示“未记录”，不能补成默认值。

保留现有查询与详细查看。日期/路径组合筛选、真正分页、汇总统计与清空为应用层/查询接口扩展，不能把现有 recent(limit) 当成完整分页。清空明确范围、记录数及其不删除归档/产物的语义；不把清历史、删除输出和清 known_files 绑定。只读状态禁用变更，无状态显示“本次不访问历史”，不能用 GUI 缓存绕过 state.mode。历史重试只重建请求和新 task id；缺失输入需重新选择，旧手动密码需重新输入，旧快照不支持时提示迁移而非静默降级。

### 密码管理

列表默认掩码；列为密码标识、来源、启用状态、置顶、成功/失败统计、使用时间（仅展示实际持久化字段）。动作覆盖添加、删除、启用/禁用、置顶/取消置顶、导入/导出、批量禁用与清理。禁用项浏览、恢复和专用置顶编辑接口需要补齐，现有 ranked_candidates 只返回启用项。清理提供保留数量/陈旧天数和预览/应用，沿用置顶保护与禁用语义，不等同永久删除。导入现接口只返回非空输入行数，重复行也计数；分类展示新增/重复/重新启用需要扩展报告，不能误把行数称为新增条数。保留错误整批回滚；写操作完成后再刷新，不能先显示成功。

查看或复制由用户显式触发，切页/失焦后重新遮罩。搜索默认只匹配非敏感元信息；不把密码放搜索历史、日志、通知、任务名或事件。数据库现为明文 TEXT，界面遮罩不代表加密存储；页面用“密码管理”，不称“安全保险库”。导出明确为包含明文密码的文件，在用户选择路径并点击导出后进行。导入/导出、清空/永久删除分别展示准确范围，不再追加无意义的通用确认。

任务密码弹层显示具体归档和任务，使用遮罩输入，支持“尝试”“跳过当前归档”“取消任务”。“成功后保存”受本任务 passwords.save_success 和状态模式共同约束；默认继承配置并可在任务启动前修改。现有 prompter 只返回密码，运行中逐次勾选保存需扩展交互契约，因此第一版弹层只展示已冻结策略，不能放一个无效复选框。批次应用选项也只能兑现核心真实支持的范围。剪贴板只保留输入框的用户粘贴操作，不能宣称自动密码候选来源已接通。

### 压缩包预览、检测和校验

“归档预览”接 `list_archive_with_listener_interactive`，以树/列表展示路径、目录标志、压缩前/后大小；大小未知显示“—”。首版不显示源模型没有的修改时间、权限或每项加密状态。树由条目路径建模，虚拟化显示，搜索在已加载条目内；核心当前返回完整 Vec，视图虚拟化不等于列表请求已可分页或有内存上限。

顶部显示格式、归档级加密状态、当前编码、内嵌偏移和“解压整个归档 / 校验完整性 / 编码对照 / 检测内嵌归档”。元数据加密时先输入密码，失败不把空列表当空归档。名称当数据展示，不把不安全路径拼为真实磁盘路径，不自动执行或打开归档成员。

编码对照复用已有原始名称字节和候选，显示同一组名称在不同编码下的结果，允许手动选择。只有用户确认的编码才写已知文件记忆；自动猜测不能覆盖人工确认。未知格式、不支持后端、缺卷、文件变化均显示可操作原因。

检测详情保留 format、offset、size（未知可见）、confidence、description 和文件感知信息；内嵌选择弹层只提供现有回调的提取/跳过/全部操作，不假装支持任意多选切片请求。

校验接受任意分卷和多组归档，显示入口及归并成员。报告将完整性、覆盖范围、密码状态分开；明确区分确认坏卷、疑似组、缺失、不可读、未检查和证据物理范围，保留追加诊断关闭、超时与强制后端。局部成功不能显示“整组健康”，疑似组不能标每卷都损坏。历史保留结构化报告，校验不更新解压完成记忆。

### 新建压缩

底层存在 `ArchiveExecutor::compress`，新建操作需覆盖输入文件/目录、输出文件、容器、压缩等级和可选密码。可选容器与加密能力根据实际 adapter 能力显示，不能写死“所有格式”。能力未知时进行明确验证再启用。

目前没有面向 GUI 的压缩工作流，7z 实现还没有消费 request.format/level：需补参数映射与能力校验，添加 engine 入口，接同一任务时间线、取消、历史、输出临时文件和可回滚提交；失败不留下看似完成的最终归档。此前菜单可标记“待接入”但不算全功能验收通过。格式、等级、密码、回退和失败清理分别测试；不承诺尚无接口的分卷创建、逐项过滤或高级 codec 参数。

## 5. 全量设置与来源解释

设置分“解压与输出、扫描与编码、密码、历史与状态、资源限制、后端、界面”。前六类映射现有 SmartZipConfig，不建立平行配置文件；界面偏好单独存窗口、主题、队列并发和投递启动方式，不含核心策略或凭据。

除快速字段外，必须覆盖：根/内层扫描模式及比例、分卷自动发现、可疑编码策略、单根命名、冲突、出错继续/停止、内层归档 keep/trash/delete、密码来源顺序/数量/统计/保存、已知密码/编码复用、state.mode/history/known_files/database、全部资源限制、交互和日志等级、后端发现及安装项。字段清单及精确枚举由 config model/统一配置文档维护，不在此重复默认值表。

每个字段可查看默认/文件/本次覆盖来源与被抑制原因，支持“恢复继承”。配置路径可查看/选择，提供初始化、校验、有效配置、来源解释和旧版本迁移预览/应用入口；符号链接、只读文件、并发编辑冲突按 store 拒绝写入。多字段保存需要 store 的单次校验与原子提交扩展，不循环 edit_config 导致半保存。

不属于持久化模型的 CLI 请求选项放在对应“新建操作 → 高级”：扫描窗口字节上限（0 为不限）、最低置信度、deep、多个手动密码、无密码尝试开关，以及本次不加载外部配置 no-config（不等于关闭状态）。扫描上限须保留根完整扫描与嵌套候选扫描的区别，不能解释为全部解析量上限。`force` 当前只有兼容字段、没有工作流消费点；重试直接建新任务，沿用碰撞策略，不提供一个假生效的“强制”开关。显式大扫描确认同样有字段但无发出/消费点，补齐扫描前实际检查/响应接线后才启用，而非依靠已有四类 prompter。强制后端在新建任务中可选，并保留详细路由开关。输出结果提供结构化复制/导出，复用 CLI 的业务字段与终态；明文密码导出始终是单独动作。

任务启动前展示编译后的策略说明；`dry-run/explain` 仅为配置计划，不能称为“将产生这些文件”的实际布局预览。`skip_completed` 当前被抑制时显示原因；logging.file 与自动剪贴板候选当前不支持，不能让控件勾选后无效。配置错误阻止启动但不破坏用户草稿。

## 6. 应用层与事件契约

这是拟新增的最小职责划分，不改 engine 的归档职责：

| 边界 | 所有权与职责 |
| --- | --- |
| AppState（GPUI 主线程） | 双窗口共享的任务摘要、选择状态、界面偏好；不持有数据库连接或阻塞扫描 |
| TaskController（GUI 应用层） | 提交/排序/取消、任务快照、有限并发、输出范围协调；入队分配稳定 JobId，Started 后关联引擎 TaskId；窗口不直接启动 engine |
| 工作执行线程 | 在本线程构造 Tokio runtime/LocalSet、连接、PasswordService、history、router 和 engine；non-Send workflow 在本线程 await |
| 交互桥 | 将四类 prompter 转为带 task_id/request_id 的 UI 请求，经 oneshot 回答；密码走专用不记录的载荷 |
| 结果投影 | listener 事件投影为摘要和时间线；最终 result 对齐终态与完整业务结果 |

每个活跃任务在固定工作线程内部创建借用连接的服务，不能把 `DbTaskHistoryRecorder` 或其 non-Send future 直接放入 `tokio::spawn`。连接初始化/迁移先串行完成；后台密码管理与任务写入采用短事务和有界 busy 等待，连接不跨 UI 线程共享。并发版本需要验证锁竞争，不随意把历史 best-effort 降级扩展为密码 CRUD 可以假成功。

`TaskEventListener` 回调必须立即返回。进度用按任务合并的最新值和非阻塞唤醒，UI 最多约 10Hz 刷新；可靠完成/失败和待决请求走独立于可丢弃进度的可靠控制状态。背压时可合并进度，不能丢失待决请求或终态；控制待决数受活跃任务数限制。业务事件仍属于唯一 TaskEvent 时间线，不因传输分层新建业务事件源。UI 过载时标识中间进度已合并，最终以 result 校准；现有核心有进度保留上限，不能承诺每个进度采样均永久保存。

test 的取消令牌通过 `TestWorkflowRequest.control` 注入，不能只设置 engine token。同步 detect 迁至后台且需补取消/隔离边界验证；不能通过 drop future 假装取消已运行的同步扫描。最终取消完成要等待真实退出；无法即时中断的阶段明确显示正在等待。

交互状态为排队 → 运行 ↔ 等待决定 → 正在取消 → 核心终态；待决是 UI 调度状态，不擅改现有 DB 终态枚举。每次只允许一个有效回答，后到/取消后的回答忽略并清除密码。两个窗口看同一个请求，点击一处后另一处同步消失。四类提示不串到其他任务；关闭弹层相当稍后处理，显式跳过和取消才返回业务决策。`interaction.mode=never` 不排无限等待弹窗，沿用 needs_decision 结果。

重试总是新任务，可引用原任务 id；不能把失败记录覆盖成成功。配置快照、事件和日志先按敏感信息策略检查后才持久化。最终提交、碰撞处理、归档路径校验、失败树清理、预算和内层回收继续由核心负责；GUI 不抢先删除输出或手写覆盖移动。

## 7. 键盘、可用性和错误

Cmd/Ctrl+O 选择输入，Cmd/Ctrl+, 打开设置，Cmd/Ctrl+1/2 切换快速/详细窗口；Tab 顺序遵循阅读顺序，任务行 Enter 打开详情，Esc 关闭非破坏性弹层而非默认取消任务。重排序有按钮和键盘替代，不依赖拖动。对话框锁定焦点并在关闭后回到触发控件；中文输入法、缩放、深浅主题和读屏单独验收。

异常以任务内持续状态呈现：缺少后端→打开后端诊断；磁盘/预算不足→显示限制和清理结果；数据库失败→保留任务结果并标明历史未保存；权限失败→展示实际路径；源文件改变→重新校验；回滚失败→保留受影响路径与人工恢复信息。通知只能摘要，不带密码，不用短暂 toast 承担唯一的失败反馈。

## 8. 实施切片与不退化验收

切片先后是依赖顺序，全部通过才称完整 GUI；不能以减少可见入口绕过最后一项覆盖审核。

| 切片 | 交付 | 必须验证 |
| --- | --- | --- |
| S0 组件与运行时验证 | 固定依赖，双窗口 Root，中文输入、外部拖放，工作线程 | 真机三平台目标矩阵；版本/feature 构建；多窗口和 UI 不阻塞 |
| S1 真实快速解压 | 快速窗口、单并发队列、统一配置、进度、取消、四种交互 | 普通/加密/嵌套/伪装归档；密码错误不污染输出；关闭窗口无孤儿任务 |
| S2 详细调度 | 队列排序、任务详情、共享窗口状态，随后加受限并发 | 同根串行、跨根并发、单盘预算、DB 锁、取消与待决竞态 |
| S3 数据与预览 | 历史/文件历史/统计、密码全量管理、条目/编码/检测/test | 与现 CLI 同输入同策略比较结果；分卷证据、旧库、只读/无状态、导入回滚 |
| S4 压缩与高级设置 | 新压缩工作流，全配置来源/安全编辑、后端诊断 | 支持格式/等级/密码 round-trip；取消/冲突/清理；配置多字段原子保存 |
| S5 完整验收 | 每项审计矩阵有 GUI 自动或人工验收记录 | 除既有缺口外无功能遗漏；性能和原生平台证据独立记录 |

关键行为场景：

1. 多个目录各拖入文件，结果仍符合首输入父目录规则；一个投递批次的刚成功密码能用于后续文件。
2. 快速投递后打开详细窗口，task id、进度、取消和输入请求一致；关闭快速窗口不重启任务。
3. 后端无进度/递归继续发现节点时，界面没有虚假 100%；后端达到 100% 但正在提交仍显示处理中。
4. 密码、编码、内嵌、冲突请求分别支持回答、稍后、取消；已取消请求的迟到回答无副作用。
5. 同名输出在最终布局后才询问；覆盖失败可回滚；失败 adapter 树清理失败禁止下一 adapter。
6. 正常/错误密码、native/外部后端、不支持 codec、损坏与缺卷，不改变既有 fallback 和密码统计语义。
7. 分卷任意卷投递、同组重复输入、局部校验通过/密码未知/诊断超时，在 UI 与原结果保持一致。
8. state.off 不打开数据库；read-only 不迁移/写库；关闭历史仍保留允许的密码记忆；清历史不删除文件。
9. 手动编码确认记忆保留；不把自动猜测覆盖到人工编码；预览乱码可对照纠正并用于解压。
10. 大条目集、事件突发、后台检测、密码库导入时仍能操作窗口；另测核心完整 Vec 的峰值内存，不以虚拟滚动掩盖。
11. 配置原子保存遇并发修改/只读/旧版本/未知字段有明确错误；排队快照和运行策略不随全局设置漂移。
12. 原型演示、单元测试、真实后端验收、平台验收与性能记录分别标注；网页交互通过不能证明 gpui-component 可运行。
