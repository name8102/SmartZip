# 原生后端的数据流续改

基线是 `3cb9327`。本轮沿探测、列表、编码、成员预览、校验、提取、提交和 GUI 展示追踪数据，沿用短生命周期 worker 与同盘事务式提交。

- worker 按操作传数据：探测只读格式和加密属性，校验保留原生逐项结果而只为失败项读取完整元数据，索引读取和子集提取只枚举选中条目。数据帧合并写入并复用接收缓冲；预览无需字符集参数。CLI 和 GUI 使用同一个索引读取结果类型。
- ZIP 中央目录只提供名称数据，删除旧 backend 外壳及无消费者的大小、加密和公共原始名称副本。ASCII 与有可靠 Unicode 标记的名称交给原生后端；混合目录只用未标记名称做编码判断。CLI `enc` 共享一次输入解析、分卷分组、口令流程和列表操作，再生成不同编码视图。
- 字节分卷按偏移定位，只持有当前卷的读取句柄，连续读取不重复 seek。提取的成员路径、句柄、实际大小和元数据归到同一写计划，同名后缀不回头重试，文件与隐式目录同名时给文件改名。预算拒绝首块时不创建空文件；写入完成时在现有句柄上设置时间和权限。
- manifest 中的文件清单直接转交预算和后续发现，不再逐路径复制；目录检查跳过不需要的 metadata 查询和空的磁盘采样。router 只在确实切换 adapter 时清除旧产出；终止失败由 staging 所有者处理。
- GUI 直接保留类型化结果，归档目录在后台建索引；未搜索或重排序时，虚拟列表共享当前目录，不复制整个目录。诊断 JSON 只在用户复制时生成。

归档越界、源身份检查、显式预算、失败清理和覆盖回滚仍由各自的数据边界负责。内嵌扫描仍识别完整范围；显式校验仍实际解码，未复用预览结果作为完整性证据。

## 验证

macOS arm64，Nix 开发环境，官方 7-Zip 26.06：

- 底层原生库契约、archive 单元测试与真实 worker 集成通过，覆盖 GBK/AES ZIP、越界路径、同名与目录冲突、索引/前缀/范围读取、写前预算和取消。分卷诊断集成 10 项通过。
- engine 的预算、材质化/回滚、原生路径、单次编码列表和完整性工作流相关检查通过。
- GUI 浏览索引 5 项与真实后台检测、列表、预览、校验、解压验收通过。未做窗口视觉验收。
- CLI 的 GBK 编码对照与显式 GBK 列表一致；从第三卷输入校验并解压真实 7z 字节分卷，产物与原文件逐字节相同。

## 性能

使用同一主机、同一库和同一批临时输入，交替运行两个 debug 版本。每项保留一次预热和五次计时；原始数据见 [samples.jsonl](samples.jsonl)，复现脚本见 [bench.py](bench.py)（分别传入两个 CLI 路径，匹配的 worker 放在各自旁边）。

| 工作负载 | 改动前中位数 | 改动后中位数 |
| --- | ---: | ---: |
| 探测 5 万成员 ZIP | 1.6447 s | 0.6844 s |
| 列表 5 万成员 ZIP | 1.4669 s | 1.2109 s |
| 校验 5 万成员 ZIP | 1.0659 s | 0.4129 s |
| 解压 128 MiB 单文件 | 0.5260 s | 0.5202 s |
| 比较 5000 成员 ZIP 的编码 | 1.4676 s | 0.2695 s |
| worker 从 5 万成员中读取 1 项 | 0.4717 s | 0.0164 s |
| 解压 2000 个同名成员 | 2.7037 s | 0.4215 s |

索引读取的 worker 输出由 10,939,275 字节降至 607 字节。128 MiB 单文件解压的样本区间重叠，耗时基本持平。
