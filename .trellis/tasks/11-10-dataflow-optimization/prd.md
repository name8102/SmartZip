# 数据流与工作流优化

## 目标与范围

用户要求系统检查重复工作、过度校验、冗余代码及无依据限制；优先功能可用性、性能和维护性，考虑结构性改动，只维护现行契约，不向上兼容。

开始时 main 干净，已 fetch 并确认与 origin/main 同步。未操作用户配置、数据库或安装。所有归档、数据库与恢复验证使用临时目录。

## 已实施

| 数据流 | 成本与改动 |
| --- | --- |
| 检测 → 后端 | probe 原来执行完整 `t`，改为元数据 `l -slt` / `lt`；完整内容校验只留给 test。 |
| 编码 → 列目录 | ZIP 编码在首次后端 list 前一次确认，删除 Auto 后再 Override 重列和对相同文件的重复评估。 |
| 提取输入 | 合并读取头部和输入错误处理，删除未消费的普通文件分类及第二次打开/读取；去重键使用原生 PathBuf，而非有损显示字符串。 |
| ZIP 元数据 → 提取/预览 | 同一打开实例用于名称解码和提取/读取；提取 listing 只解析一次。 |
| 扫描 | 文件和内存输入统一为 Read+Seek 解析，删除旧 binwalk 扫描、window 扫描及重复 ZIP/RAR/LZMA 解析路径；复用签名 matcher。ZIP EOCD 位置按输入建一次索引；同块内继续处理候选，不因每个未知长度头重读后续整块。按格式只取所需前缀。 |
| 异步发现 | scanner 用 Arc 共享；嵌套目录/内容发现移入阻塞线程，消费已有产出 inventory，不复制整份 inventory 或阻塞执行线程。 |
| 密码 | 默认读取全部启用候选；保留显式正数限额、0 不限。保序 HashSet 去重替代各层线性扫描；UPSERT RETURNING 删除二次查 ID。 |
| known_files | 删除无消费者的 names_offsets_json；无密码/编码提示的成功不再创建空行；一次 UPSERT 合并密码与人工确认编码，删除读整行、JSON 合并及双写。成功事实仍只在 file_extractions。 |
| 阶段事件 → 数据库 | 删除额外 sequence 及每次 MAX 查询，统一按插入 ID 排序。节点结束用带 partial 索引的 EXISTS 查未完成节点，终态计数一次聚合。数据库仅支持 v9，不维护迁移链。 |
| 配置编辑 | OS 文件锁替代可能因崩溃永久残留的哨兵锁，减少重复读/校验；保留提交前内容比较、原子发布和托管文件保护。 |
| GUI 队列 | 按请求 revision、队列位置与终态增量保存；100ms tick 不再反复克隆、序列化全请求。保留最新保存确认后才能启动的顺序。 |
| GUI 根节点 | 按 revision 刷新快照；一次构建活动节点索引，将 root×node 重复扫描改为线性投影。 |
| GUI 浏览/预览 | 只读浏览不因成员路径拒绝整个归档；预览复用 List 任务的后端路由器，不重新自动发现后端；仅校验目标成员，不因无关链接/路径拦截内容读取。 |

### 删除的默认或内部限制

- 递归深度默认不限，显式 `max_depth` / `--recursion-limit` 保留，0 只处理根归档；深度使用 usize，删除 u8 的 255 上限。
- 嵌套候选、扫描字节数、finding 数量默认不限；默认不再按 10 MiB 最小载荷或 4 GiB 内层文件大小过滤。用户显式预算继续生效。
- 删除 LZMA/XZ 解码器 64 MiB 内部预算，以及无效大文件扫描确认字段和两个未消费的 policy 字段。
- 删除普通后端输出 16 MiB、预览目录 4 MiB、内容内部 32 MiB/30 秒、GUI 文本/图片大小与像素固定限制；预览 max_bytes=0 不限且仍可取消。
- 删除 IPC/Finder 请求的路径数量及字节固定上限、分卷发现 4096 卷/100000 目录项上限；缺卷查找改用 HashSet。
- 删除 archive 中未使用的旧 ExtractionLimits；配置中的 ExtractionLimits 为唯一现行产出预算类型。

### 保留的必要边界与取舍

实际写盘提取仍校验路径逃逸，隔离尝试、失败回收、源文件身份和覆盖提交回滚保持原职责。诊断日志保留量与固定 I/O 读取块不是功能上限。密码不写日志或持久执行快照。

完整 stream 解码仍用于 Gzip/Bzip2/Xz/Lzma 的精确 carving 边界，避免把后续载荷截断或混入前一归档；这部分扫描与提取仍会重复解码。若要消除，需要改变“识别/精确范围/解压产物”的交付契约，而不是仅删一次调用。

分卷提取模型负责可试验的多种分组、别名与提交；test 的物理快照模型负责缺失/损坏范围证据，二者不是旧版/新版兼容链。此次删除了固定发现预算和二次查找，未把不同证据语义强塞进同一个结构。后续可在保留诊断证据的前提下共享发现结果。CLI enc 的多编码流程仍重复准备归档；跨 engine/backend 重用 listing 也需要明确元数据生命周期，目前未新增隐式全局缓存。
