# 7-Zip 动态库封装研究与迁移设计

日期：2026-11-10。状态：原生执行迁移已落地，实施范围和实际验收见 [implement.md](implement.md)。下文保留研究阶段的确认与交付记录。

## 用户确认

- 研究 `7z.dll` / `7z.so` 封装，目标是替换当前 7-Zip CLI 调用。
- 使用最新稳定 7-Zip，不维护旧版本或旧 CLI 输出解析兼容层。
- 可以调整当前调用、输出解析及相关组件设计。
- 参考 ArchiveRclick，按 SmartZip 需求独立设计。
- 本轮先交付研究与迁移设计；补充问题明确关注直接 Rust FFI 的可行性。
- 后续要求比较结构化调用相对 CLI 的能力增量，并按新能力重设计其他组件，不停留在命令替换层。

## 本轮交付

- [方案与迁移边界](design.md)：直接 Rust FFI 为首选，比较 C++ 桥接和执行隔离方式。
- [能力驱动的组件设计](capability-design.md)：来源、成员身份、执行计划、输出流、密码范围、校验与事件模型。
- [原型、复现及结果](research/README.md)：Linux 原生库构建、Rust 直接调用 8 项检查、C++ 对照 13 项检查。
- 不修改现有运行代码、配置格式或安装产物，不新增压缩创建入口。

## 后续替换的验收目标

1. probe/list/test/extract/成员预览通过库接口执行，产品运行不调用 `7z` / `7zz`。
2. 密码、错误、进度、成员选择和能力发现使用结构化数据。
3. 分卷、旧编码 ZIP、取消、隔离输出、提交回滚和真实平台打包逐项验收。
4. 删除被替代的 CLI 构造、解析、兼容测试和发现逻辑；保留独立的 Unrar adapter 与有效领域测试。

详细实施顺序及尚未实测的平台/行为统一见 design.md 第 11 节，不在此重复维护。

## 实施请求

实现原生封装并替换 CLI；按新能力改造结构，精简数据流与工作流，删除无效旧路径，不添加无依据的限制或重复验证。落地结果统一记录在 implement.md。
