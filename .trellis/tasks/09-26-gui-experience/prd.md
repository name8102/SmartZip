# GUI 桌面体验完善计划

日期：2026-09-26。状态：已开始实施；交付切片、验证证据与剩余项以 [实施记录](implement.md) 为准。

用户要求：优化并完善 GUI，使其具备成熟桌面应用的完整使用体验；先梳理计划，再按整体架构优先实施，避免被局部细节阻塞。

补充要求：界面 UI 与主题需要作为独立重点规划，覆盖整体视觉、各页面布局、组件状态和浅色/深色/跟随系统体验；从前期设计与基础实施开始交付。

## 目标与范围

让用户在界面内完成“投入归档 → 查看/配置 → 执行 → 处理例外 → 获取结果 → 查看历史/恢复任务”，每一步都知道当前状态、操作影响与下一步。

沿用 GPUI，改为同一原生窗口内的快速/完整两种显示模式，复用共享引擎、配置、任务历史、提交与恢复模型。平台优先 Linux/macOS，中文体验优先。产品范围以 [requirements.md 第 0 节](../../../docs/requirements.md) 为准：智能解压、归档浏览/有限预览、任务调度与恢复；压缩创建和 Windows 发布不属于本计划的必交付项。

下表保留规划阶段依据源码与历史截图梳理的实施前基线，不代表当前源码。后续已进行原生运行与测试，实际范围见实施记录，不能将规划矩阵当作已通过的验收。

2026-09-26 用户进一步明确：快速模式必须复用当前窗口，保留页面与草稿；预览通过归档浏览页面进入，完整性校验和内嵌检测属于当前归档的操作菜单，不平铺在任务中心。该要求取代早期双窗口设计。

## 界面 UI 与主题专项

优先级：P0 建立视觉与主题基础，P1 完成全部页面覆盖。以下为拟采用的设计方向，具体色值、尺寸和效果以原生样稿校验后定稿。

### 视觉方向与规范

- 整体采用简洁、清晰、适合长时间使用的桌面工具风格：低饱和中性色、明确的信息层级、适中的列表密度、克制的蓝色强调色，延续现有应用识别。
- 同一页面只突出当前主要动作；其余使用次级、文字或菜单动作。页面标题只保留必要层级，工具栏位置稳定，批量操作在选择后出现。
- 建立统一尺寸规范：正文建议 13–14 逻辑像素，辅助信息 12–13，页面标题 20–24；中文使用系统字体与合适回退，计数/进度等数字使用等宽数字。采用 4/8 基础间距，页面留白 16/24，圆角控制在 6–8，最终按原生可读性调整。
- 列表提供标准与紧凑密度，分别明确行高、点击区域与文本布局；字体/界面缩放独立验证，紧凑模式仍保留可见焦点和可点击目标。
- 图标统一线宽、大小和对齐，区分文件类型、文件夹、归档与任务动作；仅图标按钮提供说明和无障碍名称。复用现有矢量资产，按真实缺口补充。
- 长文件名与路径采用合理省略、完整提示与复制入口；数值单位统一；多行错误/提示可以展开，不挤压主操作或改变整页布局。
- 统一悬停、按下、焦点、选中、未激活窗口中的选中、禁用、加载、错误状态；任务进度与列表选择使用各自清晰的视觉表达。

### 各页面 UI 交付

| 页面/区域 | 布局和视觉重点 |
| --- | --- |
| 应用外壳 | 原生窗口边框/标题栏配合侧栏、统一页标题与工具栏；侧栏选中态清晰；底部状态简洁，重要错误在对应内容位置展示 |
| 任务中心 | 紧凑批次标题、对齐的归档行、可展开子项、状态与进度、按状态出现的行操作；搜索/筛选常驻；详情栏可缩放和收合 |
| 快速模式 | 清晰投递区、主要任务状态、待处理入口、结果快捷操作；常用设置容易发现，高级信息可展开；空闲/拖入/执行/等待/完成各有完整布局 |
| 归档浏览 | 可关闭归档标签、面包屑/目录导航、文件表格、可收合内容预览；目录与文件视觉可辨，选择和预览焦点明确 |
| 历史记录 | 时间/状态/名称/结果对齐的列表与详情；成功、部分成功和失败易于辨认；筛选无结果有清晰说明 |
| 密码管理 | 工具栏、遮罩密码列表、简洁统计、选择后的批量操作；明文显示状态和导出影响清楚可见 |
| 偏好设置 | 分类导航、搜索、分组表单、标题/解释/输入层级；固定可达的保存区域、修改提示与字段错误；外观设置可直接预览 |
| 系统集成与诊断 | 按平台列出能力和实际状态，动作与对象在同一区域；缺少后端与集成失败均给出可理解的处理入口 |
| 对话框与通知 | 统一宽度、标题、正文和按钮顺序；密码、冲突、编码、退出等各有专用布局；信息提示、警告和错误采用一致视觉语义 |

### 主题体系

- 提供“跟随系统 / 浅色 / 深色”，默认跟随系统，记住用户选择；系统外观变化时仅在跟随模式同步。无法取得系统主题时使用明确的默认值，手动主题仍可用。
- 浅色采用柔和灰白背景、清晰内容表面和深色正文；深色采用石墨灰层次、浅色正文及适配后的强调色。逐项设计边框、阴影、禁用和选中状态。
- 集中定义语义颜色：窗口背景、侧栏背景、内容表面、浮层、主/次文字、边框、分隔线、主操作、悬停/按下、选中、焦点，以及信息/成功/警告/失败/暂停状态。页面与共用控件通过同一套主题值取色，避免局部硬编码。
- 主题覆盖两种模式和全部组件：菜单、弹层、对话框、输入框、表格、目录树、滚动条、进度条、通知、文本预览与图片预览背景；归档图片本身保持原色。系统管理的标题栏和对话框按平台能力适配并说明限制。
- 切换主题立即应用于当前窗口，保留输入草稿、选择、目录和运行中任务；再次启动恢复偏好。主题变更重新计算应用自定义颜色，不能只更新初始化时的取值。
- 基础交付使用统一蓝色强调色；外观页同时提供列表密度和界面字号/缩放设置。更多强调色与自定义主题导入列为后续增强，不影响首轮双主题完整交付。
- 状态同时使用图标/文本，颜色不可作为唯一信息；分别检查正文、次级文字、焦点、边界和禁用状态的可辨性。若平台提供高对比度或减少动态效果偏好，先验证接入能力再声明支持。
- 动效只服务于状态变化、展开/收合、拖放反馈与进度；保持短且稳定，提供减少动态效果选项，避免进度更新造成列表跳动或抢焦点。

### 设计交付与验收

1. 先制作主窗口任务中心、快速模式和归档浏览的浅色/深色高保真样稿，连同主要待处理对话框确定视觉方向；可使用代码原型验证布局，再落到 GPUI 原生组件。
2. 同步建立组件状态样板，覆盖按钮、输入、搜索、表格、目录、标签、进度、菜单、提示与对话框；共用组件确定后再铺开历史、密码、设置等页面。
3. 对同一组测试数据保留双主题对照截图，覆盖空态、加载、运行、等待输入、部分成功、失败，以及长文件名、多选和密集列表；按屏幕尺寸与缩放检查布局。
4. 验证浅色/深色/跟随系统切换、两种模式切换、重启持久化、已打开菜单/弹层和未保存表单；全程不重启任务、不清空草稿、不产生局部错误配色。
5. 视觉规范、主题实现和原生截图属于每个切片的验收内容；早期交付可直接使用的统一外观，后续页面按同一规范扩展。

## 需要补充和完善的内容

优先级：P0 为操作可靠性与主流程必需；P1 为成熟桌面体验的完整交付；P2 为主流程稳定后独立评估的增强项。

### 1. 统一界面与桌面操作基础（P0/P1）

- 建立统一字号、间距、控件尺寸、图标、状态色和焦点规范；明确主操作、次操作与危险操作；状态同时使用文字与图标。
- 主窗口采用侧栏、操作栏、列表、可调整/收合详情区；窄窗口自动收合详情；快速模式聚焦投递、当前进度、待处理项与结果入口。
- 保留当前新任务配置默认展开行为，允许用户收合并记住偏好；高级配置渐进展开，避免常用操作被大量参数挤出。
- 加入应用菜单、上下文菜单、统一快捷键及提示：打开归档、添加解压、搜索、设置、关闭窗口；按平台采用 Ctrl/Cmd，避免与输入框快捷键冲突。
- 补齐键盘选择、Tab 顺序、焦点可见性、对话框焦点恢复、中文输入法；核验 GPUI 与目标平台的无障碍能力，不能用控件存在代替读屏验证。
- 记住窗口尺寸/位置、详情宽度与侧栏状态；多屏变化时把窗口恢复到可见范围；支持系统/浅色/深色主题。
- 所有页面具备加载、空数据、无搜索结果、失败、禁用原因和成功反馈；成功提示可短暂展示，错误与待处理状态持续可见。

### 2. 添加归档与任务管理（P0/P1）

- 明确拖放区域与落点反馈：任务页执行解压，预览页只读浏览。输入无效、文件消失、重复投递或同组分卷合并均反馈具体结果。
- “添加并配置”形成完整草稿：输入清单、输出目录、常用选项、配置来源、临时密码、开始；取消草稿不影响其他任务。
- 分离“暂停自动启动”和“暂停当前归档”，用“请求暂停/正在取消并清理”等过渡状态说明何时生效。
- 加入名称/路径搜索、状态筛选、稳定排序、多选和批量取消/重试；保留键盘替代。仅对当前可执行范围启用动作，并说明批次结束前不能单根重试的限制。
- 统一批次、逻辑归档、物理卷、嵌套子项的计数与状态；保留父归档已提交但子项失败的部分成功语义。
- 进度展示阶段、当前文件、已处理数量、耗时及后端；速度/剩余时间只在数据可靠时显示，无总量时使用不确定进度。
- 完成后提供结果摘要、打开输出/定位源文件、复制路径、只重试失败项、移除已结束会话项；移除会话项不能删除历史或输出。

### 3. 待处理事项、错误与退出（P0）

- 统一待处理入口，显示数量、归属归档与原因，允许从快速/完整模式定位对应任务。跨任务/预览提示均可发现，回答不会作用于其他任务。
- 密码交互提供显隐、失败原因、重试/跳过与明确保存策略；临时密码继续不持久化，不能因新增恢复或诊断功能泄漏。
- 冲突对话框展示实际源/目标、可取得的大小和时间、覆盖范围及重命名结果；明确“仅本项/本批同类”作用域。批量选择依赖核心支持，不能用全局 UI 状态模拟。
- 编码提供候选名称、文件名对照、手动选择与重新读取；仅允许当前后端实际支持的路径，并沿用人工确认记忆语义。
- 内嵌归档、分卷校验结果使用结构化说明；区分确认损坏、疑似、缺失和未检查，提供可用的下一步。
- 错误按缺少后端、密码、损坏、权限、空间/预算、输出冲突、历史写入、清理/回滚失败分类，显示具体恢复动作；技术事件与 JSON 收入可展开诊断。
- 用显式退出状态与对话框替代消息文本判断：继续处理、取消并清理后退出；先保证任务持久化与安全停止，再接入“保存队列并退出”。不能把关闭窗口视为强杀后端。

### 4. 可理解的持久化与恢复（P0，涉及共享核心/数据库）

- 启动时只读检查未完成任务，展示可恢复、需密码、输入缺失、等待对账/人工处理的列表；“继续恢复”成为显式用户动作，避免必须新建解压才发现旧任务。
- 将 GUI 草稿/未开始任务的持久化范围、顺序、配置快照和稳定身份补齐；根暂停状态及恢复视图沿用现有任务/节点模型，不另建平行任务库。
- GUI 行稳定关联持久 TaskId/NodeId，恢复后拥有独立进度、提示和结果，不把旧任务事件混在新提交任务中。
- 区分安全对账与实际重跑：读取状态不执行解压；恢复调度前完成必要对账。已完成节点不重复提交，缺少嵌套产物时说明重建范围。
- 说明临时密码需要重新输入、半完成归档节点从头执行；暂停状态不能在重启后被默默解除。
- 与 CLI 的同库执行所有权保持一致，冲突时说明由哪个入口处理及下一步，不自动抢占。

### 5. 归档浏览与预览（P1）

- 目录树/面包屑配合可排序文件表格，补齐名称搜索、大小/类型等可用元数据、键盘导航、路径复制和明确选择态。
- 归档标签可关闭、可切换，记住各自目录与选择；关闭时取消读取并释放预览内存。
- 预览放在可收合区域，完整覆盖读取中、空文件、不支持、超限、需要密码、失败和取消状态；保持现有大小、时间与像素预算。
- 编码切换后刷新文件名并保留可解释的导航结果；整包解压可先选择目的地与选项。
- 缓存归档目录模型并使用虚拟化列表，避免每次进度刷新重建全部目录与元素。
- 完整性校验与内嵌检测收纳在当前归档的「归档操作」菜单；原位展示执行状态和结构化结论，任务中心保留统一执行记录。
- “解压选中项”“系统程序打开成员”“从归档拖出文件”列为 P2：需单独补齐精确成员选择、安全输出与临时文件生命周期契约，不能靠 UI 包装现有整包解压宣称完成。

### 6. 历史、密码与设置（P1，其中防丢修改/破坏性操作保护为 P0）

- 历史改为结构化任务/文件列表与详情，按时间、名称、状态筛选，分页加载；可查看结果、定位存在的输出、重新执行、导出诊断。输出已移动时说明位置失效，不能改写已成功事实或去重规则。
- 密码库增加搜索、排序、分页、多选、置顶和启用状态管理；成功操作自动刷新，导入报告新增/重复/无效统计，清理条件可配置并先展示影响数量。
- 密码删除与批量清理提供明确影响确认；导出说明本地明文文件。普通通知、事件、诊断导出永远不含密码。
- 设置支持搜索、常用/高级层次、就地校验、修改标记；离页/关闭/重新加载时保留草稿或让用户选择保存/放弃/继续编辑。
- 显示全局配置、新任务默认值、单任务覆盖的生效范围；已启动任务的快照不因设置变化被悄悄改写。
- 把已支持的后端安装列表、密码来源顺序等 TOML 输入改为可增删、可排序的表单；不为尚无引擎支持的规则制作可点击空入口。
- 增加后端诊断：检测路径、版本、支持能力、发现失败原因与重新检测；首次使用缺少后端时提供可操作说明。

### 7. 系统与长期使用体验（P1/P2）

- Linux 页面提供适合本平台的打开方式/集成状态，移除错误的 Finder/.app 引导；按实际支持能力展示安装、移除和修复动作。
- macOS 验证 Finder 打开/快速解压、默认关联与应用位置变化；Linux 验证 .desktop、多选打开与参数转发，再分文件管理器接入右键动作。
- 统一重复启动/打开请求路由，已有实例接收新文件并定位当前窗口的相应模式；文件名含空格、中文与特殊字符时不丢失输入。
- 提供完成、失败和需要处理的系统通知与应用内通知，避免逐文件通知轰炸；点击通知定位任务，权限不可用时保留应用内反馈。
- 增加关于、版本、快捷键帮助、配置/日志位置和诊断导出；第一次启动只引导必要设置，保持离线可用。
- 托盘/菜单栏后台模式、自动更新、更广文件内容预览、多语言属于 P2。自动更新另需签名、分发与失败回退方案，不纳入当前 GUI 重构的隐含承诺。

## 技术边界与依赖

- 按页面和真实职责逐步拆分当前 `ui.rs`：应用外壳、任务、交互请求、归档预览、历史、密码、设置。拆分服务于此次行为修改，不预建通用框架。
- UI 共用组件与主题值集中维护，系统主题订阅按 GPUI 实际接口接入；外观与窗口偏好保存为应用偏好，不混入解压策略快照，也不因主题变化重新构建归档执行环境。
- 显式管理退出、加载、错误与待处理状态，避免通过提示文字推导控制逻辑。异步读取采用请求身份/版本，防止切页后旧结果覆盖当前内容。
- GUI 消费共享事件和执行状态，核心继续负责安全路径、资源预算、后端、暂存、提交、回滚与回收。GUI 不复制文件提交或自行清理引擎 staging。
- 持久化与恢复先确定 schema 迁移、旧历史兼容和安全停止语义，再开放对应按钮；缺少接口时以共享核心切片补齐。
- “应用到同类冲突”、候选编码重读、选择性解压、完整根状态恢复都是需要后端能力的工作，不能当成纯界面改动估算。
- [目标文件系统路径兼容性方案](../09-22-filesystem-path-policy/prd.md) 尚未实施。本计划只预留结构化路径变更/错误展示；不把长路径与非法名称转换当作 GUI 已可解决的问题。
- 当前待估时工作包括 GPUI 原生无障碍能力、恢复数据库变更、Linux 集成覆盖。S0 后按切片估时，不在未验证依赖时承诺固定工期。

## 验证矩阵

1. **模型与交互测试**：状态可用动作、多个任务等待输入、任务/预览切换、模式切换后的回答一致、设置草稿、异步旧响应失效、筛选分页与选择保留。
2. **真实后端验收**：普通 ZIP/7z、加密、分卷/缺卷、嵌套部分失败、乱码、输出冲突、权限/空间失败、取消清理；核对结果字节、源文件和旧输出保留。
3. **恢复验收**：未开始草稿、根暂停、等待密码、解压中、提交前后中断；核对任务身份、配置、输出、临时文件和旧历史，不能只验证 GUI 行恢复显示。
4. **原生体验验收**：Linux/macOS 分别验证窗口、菜单、键盘、中文输入法、拖放、系统打开、多屏、100%/150%/200% 缩放、深浅主题；读屏与焦点结果单列。使用临时归档和隔离配置，不操作用户密码库或真实关联作为无提示测试。
5. **性能验证**：建议用 100/1000 个任务、1 万/10 万个归档条目、分页历史与密码库建立分级样本；测量首次可交互、滚动、搜索、事件刷新、内存、取消响应。根据目标机器基线确定门槛；样本规模是规划，不是现有性能结论。
6. **UI 与主题验证**：所有页面和弹层覆盖浅色/深色与各交互状态；系统主题变化、两种模式切换和重启偏好正确；长路径、窄窗口、不同密度与缩放无关键内容遮挡；正文/状态/焦点清晰可辨，减少动态效果可用。原生截图与行为验证同时记录。

最终交付要求：常用流程都有明确状态、动作和失败出口；危险操作影响可见；重启行为与界面承诺一致；原生与真实后端证据分开记录。自动测试通过不等于视觉、跨平台或性能验收通过。
