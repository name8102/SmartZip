# Requirements Baseline Migration

## Goal

将旧 `docs/requirements.md` 中仍有效的产品目标、范围与验收口径迁移到 Trellis，并收敛为适配当前阶段的需求基线。

本任务先做“迁移”，再做“纠偏”：先把旧需求文档和相关设计文档里的有效内容落到 Trellis，再明确哪些目标已经后置或缩小范围。

## Confirmed Facts

- 旧需求文档仍包含“大版本跨平台重写 + GUI/CLI 同交付”的历史目标。
- 父任务已确认本轮近期目标调整为“核心功能 + 可用 CLI”，GUI 延后。
- `docs/design.md` 中部分产品边界已比 `docs/requirements.md` 更接近现状，需要一并纳入迁移判断。
- 旧需求文档仍包含大量有价值的能力边界：智能解压、分卷、密码流程、ZIP 编码、内嵌压缩包检测、输出路径与后处理、安全与可恢复性。

## Requirements

- 需求基线必须明确近期产品价值排序：复杂网络归档解压优先于 GUI、压缩、预览和系统集成。
- 明确第一阶段交付是 CLI 驱动的核心能力，而不是 GUI 与 CLI 同步完工。
- 在迁移时必须保留旧文档中仍有效的行为性需求，尤其是：
  - 单包/批量解压
  - 分卷首卷识别与非首卷跳过
  - 密码自动尝试、补输、成功记录
  - ZIP 文件名编码处理
  - 内嵌压缩包检测
  - 目标路径选择、覆盖/删除策略
  - 批量任务失败隔离和可恢复性
- 保留与当前实现和修复工作直接相关的需求：
  - 智能解压
  - 分卷识别与处理
  - 加密压缩包密码尝试
  - ZIP 文件名编码处理
  - 内嵌压缩包检测
  - 清晰的 CLI 行为与退出码
- 将明显后置的需求降级为后续阶段：
  - GUI 工作台
  - 压缩工作流完善
  - 预览/打开
  - 系统集成
  - 打包发布
- 新 PRD 需明确哪些内容来自旧文档，哪些是本轮重新裁剪后的结论。
- 文档必须明确区分三类条目：
  - 迁移后仍作为当前需求基线的条目
  - 保留为中长期方向但不属于本轮交付的条目
  - 因现实实现状态或产品决策而被降级/废弃的条目

## Baseline Scope To Preserve

- 核心工作流
  - `smartzip extract <paths...>` 应成为近期主交付入口。
  - 处理来自互联网的不可信归档应是第一优先级，而不是通用压缩平台建设。
- 必保留的能力
  - 单包解压与批量解压
  - 多层嵌套与内嵌压缩包检测
  - 分卷首卷识别与非首卷跳过
  - 密码候选自动尝试、交互补输、成功记录
  - ZIP 文件名编码自动或显式处理
  - 明确失败原因与 CLI 退出码
- 后置能力
  - GUI 工作台与密码库 UI
  - `compress` 完整实现
  - `open` / 预览能力
  - 文件管理器集成
  - 发布与打包

## Migrated Baseline

### Product Goal

- SmartZip 的核心价值不是“普通压缩软件”，而是围绕复杂网络归档提供更可靠的智能解压体验。
- 近期价值排序保持为：
  - 复杂网络归档解压
  - 可用的 CLI 工作流
  - 可靠的密码、分卷、编码与嵌套处理
- 不再把 GUI、预览、系统集成视为当前阶段 blocker。

### Current Delivery Boundary

- 当前阶段主入口：
  - `smartzip extract <paths...>`
  - 必要时保留 `detect` 作为辅助诊断入口
- 当前阶段必须围绕 Linux/macOS CLI 的核心能力验收。
- Windows 兼容、GUI 工作台、压缩工作流、预览/打开、系统集成均后置。

### Extraction Behavior Requirements

- 单个压缩包解压
  - 如果最终结果只有一个文件或一个文件夹，应支持直接落到目标目录。
  - 如果最终结果包含多个项目，应支持形成以压缩包命名的输出目录。
- 多个压缩包批量解压
  - 每个输入独立处理。
  - 单个输入失败默认不阻塞其他输入继续执行。
  - 最终结果应能区分全部成功、部分成功、全部失败。
- 输出目标策略
  - 目标路径选择必须可预测，不能同一类输入出现不稳定落盘。
  - 路径冲突默认不直接覆盖，应采用可解释策略，例如追加后缀或显式确认。
  - 删除源文件必须默认关闭，且仅在成功提交后才允许执行。

### Password Requirements

- 支持的候选来源至少包括：
  - 空密码
  - 直接父归档成功密码
  - 祖先链最近成功密码
  - 当前批次最近命中密码
  - 上次成功密码
  - 剪贴板密码
  - 用户密码库
  - 用户交互补输密码
- 正确密码的期望行为：
  - 正确密码应稳定通过，而不是在 `test` 与 `extract` 之间出现结果分叉。
  - 成功密码可记录并供后续排序复用。
- 错误密码的期望行为：
  - 应能与压缩包损坏、格式不支持、I/O 错误区分。
  - 单次批量任务内不应对同一归档重复无意义尝试。
- 排序与规模要求：
  - 默认智能模式优先尝试排序后的高价值候选。
  - 允许后续进入深度模式继续遍历剩余密码。
  - 大密码库场景应以 Top N + 增量补充为基本思路，而不是全量无差别尝试。
- 记录要求：
  - 仅在明确 `WrongPassword` 时记录失败惩罚。
  - 成功密码默认允许保存到本地 SQLite，但需要清晰告知其为本地可读存储。

### Multipart And Nested Requirements

- 分卷处理
  - 必须识别 `.part1.rar` / `.partN.rar`、`.001` / `.002` 等常见模式。
  - 默认跳过非首卷输入。
  - 缺卷、误卷和首卷识别失败需要有明确反馈。
- 嵌套与内嵌
  - 支持多层嵌套解压。
  - 支持检测文件内容中的内嵌压缩包，而不只看后缀。
  - 批量任务中的递归处理不应让一个分支的失败阻塞其他可继续分支。
  - 根输入可以忽略后缀限制并扫描 magic bytes；内层文件默认只自动展开明确归档后缀和分卷包。
  - 激进内嵌扫描必须显式启用，并受大小、finding 数量和容器排除规则约束。

### Encoding Requirements

- 编码处理需求仅针对 ZIP 文件名场景作为当前重点。
- 默认应提供自动处理路径；必要时允许 `--encoding <name>` 覆盖。
- 低置信度或不可判定场景至少要有可解释的 CLI 行为，而不是静默落盘乱码。
- 当前阶段先要求“有明确处理路径和边界”，不要求扩展为所有格式统一编码检测框架。

### CLI Contract Requirements

- CLI 是当前阶段的主交付界面，因此必须保证：
  - 多输入命令的参数模型清晰
  - 批量任务中的交互行为不混乱
  - 错误信息和退出码可用于脚本集成
  - 用户能看懂当前处理的是哪个输入、哪个阶段、为何失败
- 当前阶段优先保留或明确的 CLI 能力：
  - `smartzip extract <paths...>`
  - `smartzip detect <path>` 作为辅助诊断
  - `smartzip password ...` 作为密码库维护入口
- 退出码契约应至少区分：
  - 成功
  - 通用失败
  - 参数错误
  - 部分成功
  - 密码错误
  - 格式不支持
  - 文件损坏
  - 用户取消
  - 安全检查失败

### Safety And Recovery Requirements

- 离线可用，不依赖网络。
- 大文件与深层嵌套处理不能依赖一次性无界读入内存。
- 失败或取消后不应留下难以识别的中间目录。
- 解压流程需要防御路径穿越、危险符号链接和不安全覆盖。
- 根归档默认保留；自动删除内层归档时必须以“成功提交后”作为前提。
- 安全预算与提交策略：
  - 默认应保留磁盘安全余量。
  - 预算触发时应暂停、提示并回滚未完成的临时解压目录，而不是静默继续。
  - 默认使用同盘临时目录解压、校验、再提交。
  - 超大归档可提供快速模式，但不能把事务式安全默认降级。

## Deferred Baseline

- GUI 设置界面、任务工作台、密码库 UI。
- `compress` 完整工作流。
- `open` / 归档预览。
- 平台级系统集成。
- 打包发布与 bundled `7zz` 策略。

## Historical Statements Downgraded

- “第一版 GUI + CLI 同步交付”降级为历史目标，不再作为当前基线。
- “跨平台桌面完全重写”保留为长期方向，但不作为当前阶段验收口径。
- “locale/编码检测默认可用”不能直接继承为当前事实，只能保留为需求目标。
- GUI、系统集成、预览/打开相关第一版必须支持的条目，全部降级为后续阶段。
