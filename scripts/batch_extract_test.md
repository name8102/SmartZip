# 批量解压后校验失败归档

```bash
python3 scripts/batch_extract_test.py /源目录 /目标目录 --ask-password
```

需要 Python 3.9+ 和支持当前 JSON/历史接口的 SmartZip。可以用
`--smartzip /绝对路径/smartzip` 指定程序。默认读取源目录直属普通文件；
`--recursive` 包含子目录，不跟随符号链接。不会递归解压包内归档。
源目录、目标目录必须互不包含，源文件保留。

`--ask-password` 隐藏读取一个密码，可重复指定以输入多个候选密码；
省略时沿用 SmartZip 已有密码库。脚本不记录命令行或候选密码，
但调用 SmartZip 的 `-p` 参数仍可能被本机进程查看；SmartZip 自身可能记忆成功密码。

脚本使用 `--no-config`，避免本机配置关闭历史、遇错即停或改变输出行为；
仍使用默认数据库与密码库。强制重新尝试输入，目标冲突采用重命名，不覆盖已有输出。
输入按参数大小分批，每批由 SmartZip 自动识别和去重分卷；跨批分卷可能重复尝试。
不按扩展名过滤，普通文件也提交给 SmartZip 判断。

解压结束后读取各任务的逐文件历史，只把 `status=failed` 的输入交给 `test`。
跳过项单独记录，不当成损坏；普通文件、需要密码或交互决策等情况可能属于跳过项。
历史缺失或失败计数不匹配会明确标为报告不完整，不根据错误字符串猜文件名。

目标目录下自动创建独立 `smartzip-report-*` 目录，也可通过 `--report-dir`
指定尚不存在且位于源目录外的路径。报告包括：

- `summary.txt`：确认坏卷、疑似卷组、缺失、不可读、未检查范围及内部损坏条目。
- `report.json`：失败、跳过和完整校验报告。
- `extract-N.json`、`history-N.json`、`test-N.json`：各阶段证据及对应 stderr 文件。

疑似组不代表组内每卷都坏。内部损坏条目是后端诊断信息，不保证完整枚举。
解压失败也可能由密码、权限、磁盘或预算导致，不能直接认定损坏。
默认追加诊断预算每组 60 秒，可用 `--diagnostic-timeout` 修改；完整 test 本身不受此时限限制。
已损坏归档不会做抢救式部分输出。Ctrl+C 保存已收集的部分报告。

脚本退出码：0 无失败或跳过；1 存在失败或跳过（查看报告）；2 脚本错误或报告不完整；130 中断。

## 本次验证与已知限制

2026-09-19 使用本地 `target/debug/smartzip` 和真实 7z 后端验证：正常 ZIP、
人为破坏载荷的 ZIP、AES 加密 ZIP、加密 7z 分卷、缺少中间卷、中文和空格路径。
损坏 ZIP 被确认，缺卷单独归类；只校验历史中的失败输入，报告未包含输入密码。

验证发现的 `.7z` 卷号误识别及完整候选组试解压已在源码修复，见
[修复与验证记录](../.trellis/tasks/09-19-volume-grouping-fallback/implement.md)。
使用旧二进制仍可能遇到 `grouping_ambiguous`；用 `--smartzip` 指向重新构建的
程序。脚本不自动重命名源文件，也不把解压失败直接当作确认损坏。
