# SmartZip 跨平台桌面版重写需求草案

> 阶段：需求确认草案  
> 范围：Linux / macOS 优先，兼顾 Windows 的跨平台桌面完全重写  
> 交付形态：GUI + CLI  
> 来源：现有 `README.md`、`ini.md`、`SmartZip.ahk`、`Contextmenu.ahk` 调研，以及需求确认

## 1. 项目目标

SmartZip 当前是基于 AutoHotkey v2 和 7-Zip 的 Windows 桌面增强工具，核心价值不是“普通压缩软件”，而是围绕 7-Zip 提供更智能的批量解压、密码尝试、解压后整理、嵌套/内嵌压缩包处理、文件管理器集成和简化操作流程。

跨平台重写的目标是：

1. 完全重写为跨平台桌面应用，优先支持 Linux 与 macOS，后续兼顾 Windows。
2. 第一版同时提供 GUI 与 CLI。
3. 保留并增强现有 SmartZip 的核心智能解压体验。
4. 将 Windows/AutoHotkey/注册表/COM/7zG 窗口控制等平台耦合逻辑替换为跨平台架构。
5. 建立清晰的配置、数据库、日志、任务、压缩后端和平台适配层。
6. 不要求兼容旧版 `SmartZip.ini` 配置；可重新设计配置与数据存储。

## 2. 现有项目概况

### 2.1 当前技术栈

- 主程序：`SmartZip.ahk`
- 辅助右键入口：`Contextmenu.ahk`
- 配置说明：`ini.md`
- 用户说明：`README.md`
- 图标/截图：`ico.ico`、`pic/`
- 运行依赖：Windows、AutoHotkey、7-Zip Windows 可执行文件：
  - `7z.exe`
  - `7zG.exe`
  - `7zFM.exe`

### 2.2 当前核心入口

```bash
SmartZip.exe x  file1 file2 ...   # 智能解压
SmartZip.exe xc file1 file2 ...   # 手动指定代码页解压
SmartZip.exe o  file1             # 用 7-Zip 打开；非压缩包时进入添加压缩包界面
SmartZip.exe a  file1 file2 ...   # 压缩
```

另有：

- 直接运行 `SmartZip.exe` 打开设置界面。
- 拖拽文件到设置界面触发智能解压。
- 拖拽文件到 `SmartZip.exe` 触发智能解压。
- 通过 `Contextmenu.exe` 从资源管理器选中文件读取剪贴板路径后转交主程序。
- 注册 Windows 右键菜单和 SendTo 菜单。

## 3. 目标用户

1. 经常下载压缩包、需要批量解压的 Linux/macOS/Windows 桌面用户。
2. 需要自动尝试常用密码、剪贴板密码、上次成功密码的用户。
3. 需要处理嵌套压缩包、文件内嵌压缩包、分卷包、乱码文件名、解压后清理/改名规则的用户。
4. 希望通过 GUI、CLI、拖拽、文件管理器动作快速触发压缩/解压的高级用户。
5. 希望跨平台保留 SmartZip 工作流的用户。

## 4. 平台矩阵与优先级

| 平台 | 优先级 | 第一版目标 | 说明 |
| --- | --- | --- | --- |
| Linux | P0 | 必须支持 | 优先实现；建议优先支持 AppImage 或 Flatpak，随后补充 deb/rpm。 |
| macOS | P0 | 必须支持 | 优先实现；支持 Apple Silicon，Intel 视构建成本决定。 |
| Windows 10/11 | P1 | 兼顾支持 | 可稍后完善 Windows 右键菜单/发送到菜单等旧体验。 |

实现顺序建议：

1. 跨平台核心引擎 + CLI。
2. 基于 Rust/GPUI 优先验证并实现 Linux/macOS GUI。
3. 完成智能解压、密码数据库、locale 检测、内嵌压缩包检测等核心工作流。
4. 文件管理器/系统集成作为低优先级增强项，在 MVP 后分平台补齐。
5. Windows GUI 与系统集成后续补齐。

## 5. 功能需求

### 5.1 智能解压

必须支持：

1. 单个压缩包解压：
   - 若解压后只有一个文件或文件夹，将其移动到目标目录。
   - 若解压后有多个项目，创建以压缩包文件名命名的文件夹。
2. 多个压缩包批量解压：
   - 每个压缩包独立处理。
   - 单个任务失败不影响后续任务，除非用户选择停止。
3. 密码处理：
   - 支持空密码、上次成功密码、剪贴板密码、用户密码库。
   - 密码失败后允许用户手动输入。
   - 支持自动保存成功密码。
   - 支持基于数据库统计的密码排序和权重更新。
   - 支持按使用频率、最近使用时间、来源、文件名/路径匹配度调整尝试顺序。
   - 支持自动清理低价值密码，例如长期失败、长期未使用、超过数量上限。
4. 加密压缩包检测：
   - 能在解压前判断是否需要密码。
   - 能区分密码错误、非压缩包、压缩包损坏、格式不支持等结果。
5. locale / 编码检测：
   - 不再要求用户手动指定 locale 作为主要流程。
   - 应自动检测压缩包文件名编码/locale，防止解压后文件名乱码。
   - 可在 GUI 中展示检测结果和置信度。
   - 检测低置信度时允许用户确认或切换候选编码。
   - CLI 可提供 `--encoding auto`、`--encoding <name>` 作为高级覆盖选项，但默认必须自动检测。
6. 解压后成功判断：
   - 首选进程退出码或库级错误码。
   - 必要时参考输出文件大小、文件数量、错误输出和目标目录变化。
7. 解压后处理：
   - 删除空文件夹。
   - 按正则删除指定文件。
   - 按后缀、文件名包含、正则规则重命名。
8. 嵌套压缩包：
   - 可配置单文件嵌套解压。
   - 可配置多文件/文件夹内第一层或多层嵌套解压。
   - 嵌套压缩包解压成功后可删除原嵌套包。
9. 文件内嵌压缩包检测：
   - 检测文件内容中是否存在内嵌压缩包，而不只依赖文件后缀。
   - 支持按 magic bytes / 文件签名识别 zip、7z、rar、gzip、tar 等常见格式。
   - 支持扫描自解压包、伪装后缀文件、拼接文件中的压缩段。
   - 检测到内嵌压缩包时，应在 GUI 中提示，并允许提取或继续智能解压。
   - CLI 应提供检测命令或选项，例如 `smartzip detect <path>` / `smartzip extract --scan-embedded <path>`。
10. 分卷压缩包：
    - 识别 `.part1.rar` / `.partN.rar`。
    - 识别 `.001` / `.002` 等序列。
    - 默认跳过非第一卷。
11. 排除规则：
    - 可按后缀排除解压。
    - 可按文件名包含排除解压。

### 5.2 压缩

必须支持：

1. 单个文件压缩为同名压缩包。
2. 多个文件/文件夹混合时压缩为当前目录名压缩包。
3. 选中项全为文件夹时，每个文件夹生成一个独立压缩包。
4. 默认压缩格式和压缩参数可配置。
5. 输出文件名冲突时自动追加 `_1`、`_2` 等后缀。
6. 支持 GUI、拖拽和 CLI 触发。

建议第一版优先支持创建 zip 和 7z，其他格式视后端能力支持。

### 5.3 智能打开 / 预览

必须支持：

1. 如果目标是压缩包，使用内置压缩包内容浏览器或系统可用工具打开/预览内容。
2. 如果目标不是压缩包，进入“添加到压缩包”流程。
3. 支持额外可打开格式配置，例如 iso、apk、wim、exe。

注意：现有版本依赖 `7zFM.exe`，跨平台版不能直接复用，应改为内置预览或平台默认打开策略。

### 5.4 GUI 应用

第一版必须提供 GUI，至少包含：

1. 设置界面。
2. 批量任务进度界面。
3. 拖拽文件到窗口。
4. 密码数据库管理界面。
5. 密码统计信息：成功次数、失败次数、最近使用时间、来源、排序权重。
6. locale/编码检测结果展示与手动修正入口。
7. 解压规则管理：
   - 格式识别规则
   - 内嵌压缩包检测开关
   - 排除规则
   - 删除规则
   - 重命名规则
8. 压缩参数设置。
9. 日志查看。
10. 系统集成设置。
11. 深色模式建议支持。
12. 多语言建议预留，第一版至少中文界面。

### 5.5 CLI

第一版必须提供 CLI。

建议主命令：

```bash
smartzip extract <paths...>
smartzip extract --encoding auto <paths...>
smartzip extract --encoding gbk <paths...>
smartzip extract --scan-embedded <paths...>
smartzip compress <paths...>
smartzip open <path>
smartzip detect <path>
smartzip settings
```

可选保留简短别名，但不要求兼容旧版：

```bash
smartzip x <paths...>
smartzip a <paths...>
smartzip o <path>
```

CLI 需要返回明确退出码，便于脚本集成。

### 5.6 系统集成

系统集成优先级低于核心引擎、CLI、GUI、密码数据库、locale 检测和内嵌压缩包检测。第一版可以只提供基础安装入口、打开方式和拖拽能力；深度文件管理器集成可作为后续增强。

Linux：

- `.desktop` 文件。
- 文件管理器动作按环境分级支持：Nautilus、Dolphin、Thunar。
- 拖拽到应用图标或窗口。

macOS：

- Finder 快速操作或服务。
- “打开方式”集成。
- 拖拽到应用图标。

Windows：

- 右键菜单。
- SendTo 菜单。
- 拖拽到 exe。
- 可选文件关联。

系统集成应通过独立平台适配层实现，不能污染核心压缩引擎。

## 6. 格式支持需求

### 6.1 第一版必须识别/解压

| 格式 | 解压 | 压缩 | 备注 |
| --- | --- | --- | --- |
| zip | 必须 | 必须 | 基础格式；也用于内嵌检测。 |
| 7z | 必须 | 建议必须 | SmartZip 与 7-Zip 能力绑定较深。 |
| rar | 必须 | 不要求 | 通常仅解压。 |
| tar | 必须 | 建议支持 | Linux/macOS 常用。 |
| gz/gzip | 必须 | 建议支持 | 常见压缩格式。 |
| bz2 | 必须 | 建议支持 | 当前默认识别。 |
| xz | 建议支持 | 建议支持 | Linux 常见。 |
| cab | 建议支持 | 不要求 | 当前默认识别。 |
| 001/分卷 | 必须 | 不要求 | 重点是识别和跳过非首卷。 |

### 6.2 第一版建议可打开/预览

- iso
- apk
- wim
- exe 自解压/资源类包

### 6.3 可配置格式规则

需要保留或增强：

- 明确后缀列表。
- 后缀正则规则，例如纯数字后缀。
- magic bytes / 文件签名规则。
- 内嵌压缩包扫描规则。
- 仅用于打开/预览的格式列表。

## 7. 数据与配置需求

不要求兼容旧版 `SmartZip.ini`。

建议采用“配置文件 + SQLite 数据库”的组合：

1. 配置文件保存低频变更设置：
   - GUI 设置
   - 默认压缩格式/参数
   - 规则开关
   - 日志等级
   - 系统集成偏好
2. SQLite 保存高频与可查询数据：
   - 密码库
   - 密码统计
   - 任务历史
   - 文件名/路径模式与密码成功关系
   - locale/编码检测历史
   - 日志索引

存储位置遵循平台标准目录：

- Linux：`~/.config/smartzip/` 与 `~/.local/share/smartzip/`
- macOS：`~/Library/Application Support/SmartZip/`
- Windows：`%APPDATA%/SmartZip/`

密码可以不加密，但必须满足：

1. GUI 明确提示密码将以本地明文或可读形式保存。
2. 默认不上传密码、文件名、日志。
3. 支持导出/清空密码数据库。
4. 支持按条件清理密码。
5. 数据库读写需要避免频繁全表扫描，保证大量密码下的尝试排序性能。

## 8. 密码尝试与排序改进

相比旧版“固定列表 + 使用次数排序”，新版应支持更细粒度策略：

1. 密码来源：
   - 空密码
   - 剪贴板
   - 最近成功密码
   - 用户手动输入
   - 用户导入密码
   - 文件夹名/文件名派生密码
   - 历史同来源/同目录/同命名模式成功密码
2. 排序因素：
   - 全局成功次数
   - 当前文件名匹配度
   - 当前目录匹配度
   - 最近使用时间
   - 最近失败次数
   - 文件来源标签，后续可扩展
3. 失败处理：
   - 对同一个压缩包失败后，不应在同一任务中重复尝试。
   - 记录失败次数，但避免一次批量任务导致密码权重被过度惩罚。
4. 成功处理：
   - 成功密码权重提升。
   - 记录与文件名、目录、压缩包类型、可能来源的关系。
5. 性能要求：
   - 大密码库下先取 Top N 候选，再按策略补充。
   - 支持索引：最近使用、成功次数、来源、路径模式等。

## 9. locale / 编码检测需求

目标是防止解压后文件名乱码，而不是让用户主动选择代码页。

必须支持：

1. 自动检测压缩包内文件名编码。
2. 对候选编码打分并选择最可能的编码。
3. 常见候选至少包含：UTF-8、GBK/GB18030、Big5、Shift_JIS、EUC-KR。
4. 检测低置信度时：
   - GUI 提示用户确认。
   - CLI 给出警告，并允许指定 `--encoding` 覆盖。
5. 解压前尽量预览文件名，避免错误编码落盘。
6. 将用户修正结果记录到数据库，供后续相似文件名/来源使用。

## 10. 压缩后端方案与优缺点

后端可以继续依赖外部 7-Zip/7zz，也可以使用内置库。建议设计后端抽象层，允许组合使用。

### 10.1 外部 7zz / 7-Zip CLI

优点：

- 格式支持强，尤其是 7z、rar、分卷、自解压包等。
- 行为接近现有 SmartZip。
- 授权和实现风险相对低。
- 可先快速实现 MVP。

缺点：

- 需要随应用打包或要求用户安装。
- 进度、错误和编码信息需要解析 CLI 输出。
- 不同平台二进制和路径管理复杂。
- 与 GUI 深度集成不如库 API 直接。

### 10.2 libarchive 等内置库

优点：

- 更容易做库级进度、错误处理和安全检查。
- 更适合内置预览、路径检查、Zip Slip 防护。
- 不依赖外部进程，分发体验更统一。

缺点：

- 7z/rar/加密/分卷支持可能不如 7zz 完整。
- 绑定和跨平台打包成本更高。
- 授权、能力差异、边界格式需要逐一验证。

### 10.3 混合后端（建议）

优点：

- 默认用内置库处理 zip/tar/gz 等常见格式。
- 对 7z/rar/复杂分卷/疑难包回退到 7zz。
- 性能、安全、格式覆盖可以平衡。
- 后续可替换或扩展后端。

缺点：

- 架构复杂度更高。
- 同一功能在不同后端行为可能不一致，需要统一抽象和测试。

建议 MVP 采用“后端抽象 + 7zz 优先或混合后端”的设计，技术选型阶段进一步确认。

## 11. 日志与任务记录

必须支持：

1. 操作日志等级：
   - 关闭
   - 删除
   - 重命名
   - 命令错误
   - 命令成功
   - 其他/调试
2. 命令输出调试日志。
3. 每个任务记录：
   - 操作类型
   - 输入路径
   - 输出路径
   - 使用的格式/参数
   - 是否成功
   - 错误原因
   - 耗时
   - 尝试密码数量，不记录明文到普通日志
   - locale/编码检测结果
   - 是否发现内嵌压缩包
4. GUI 内查看日志。
5. 日志文件和数据库位置遵循平台标准数据目录。

## 12. 非功能需求

1. 跨平台：核心逻辑不得依赖 Windows 注册表、COM、AutoHotkey 窗口控制。
2. Linux/macOS 优先：开发和验收优先覆盖 Linux 与 macOS；系统集成不作为 MVP 阻塞项。
3. 离线可用：压缩/解压过程不得依赖网络。
4. 隐私：默认不上传用户文件、文件名、密码、日志。
5. 大文件：支持至少 10GB 级别文件；进度展示不能依赖一次性读入内存。
6. 稳定性：任务失败不能留下难以识别的临时目录；取消任务应清理临时文件。
7. 可恢复性：批量任务中单个文件失败不应影响后续任务，除非用户选择停止。
8. 安全：
   - 防止 Zip Slip 路径穿越。
   - 解压前检查绝对路径、`../`、符号链接等风险。
   - 删除源文件必须可配置且默认关闭。
   - 建议使用回收站/废纸篓而非永久删除。
   - 内嵌压缩包扫描需要限制递归深度和最大扫描大小。
9. 性能：
   - 任务进度应实时更新。
   - 大密码库排序应使用数据库索引和候选集策略。
   - 对大量文件规则匹配应可接受。
10. 可测试性：核心引擎需可单元测试，不依赖 GUI。
11. 可维护性：平台集成、GUI、压缩引擎、配置、数据库、日志分层。

## 13. 建议架构边界

完全重写时建议拆分为：

1. `core`：任务模型、智能解压决策、规则引擎、路径冲突处理。
2. `archive`：压缩后端抽象，封装 7zz/libarchive/系统工具。
3. `passwords`：密码候选生成、排序、统计、数据库读写。
4. `encoding`：locale/文件名编码检测与修正。
5. `scanner`：magic bytes、文件签名、内嵌压缩包检测。
6. `config`：配置加载、保存、迁移。
7. `db`：SQLite schema、索引、迁移。
8. `ui`：桌面 GUI。
9. `cli`：命令行入口。
10. `platform`：Linux/macOS/Windows 系统集成。
11. `logging`：日志与任务历史。
12. `security`：路径安全、删除策略、资源限制。

## 14. 验收标准

第一阶段需求验收：

1. 已确认目标平台优先级为 Linux/macOS 优先，Windows 兼顾。
2. 已确认完全重写，不以 AutoHotkey 代码为长期基础。
3. 已确认第一版交付 GUI + CLI。
4. 已确认不要求兼容旧版配置。
5. 已确认密码可以本地明文保存，并可使用数据库提升性能。
6. 已列出现有核心功能，并加入密码排序改进、locale 自动检测、文件内嵌压缩包检测。
7. 已列出压缩后端方案及优缺点。

未来 MVP 验收建议：

1. Linux 与 macOS 均能运行 GUI。
2. Linux 与 macOS 均能通过 CLI 执行解压、压缩、检测、打开/预览操作。
3. Windows 至少能运行 CLI 或基础 GUI，完整系统集成可后续补齐。
4. 能成功解压 zip、7z、rar、tar、gz、bz2。
5. 能创建 zip，建议能创建 7z。
6. 能批量解压并正确处理单文件/多文件输出目录。
7. 能基于数据库尝试密码、记录成功/失败并动态排序。
8. 能自动检测文件名编码，降低乱码风险。
9. 能识别并跳过非首部分卷。
10. 能检测文件内容中的内嵌压缩包。
11. 能执行解压后重命名/删除规则。
12. Linux/macOS 至少有基础文件管理器集成说明或实现。

## 15. 当前发现的跨平台重写风险

1. `7zG.exe` 进度窗口解析无法跨平台复用，需要改为解析 CLI 输出或使用库级 API。
2. `7zFM.exe` 打开压缩包无法跨平台复用，需要内置预览或平台默认打开策略。
3. Windows 注册表右键菜单逻辑必须重写为平台适配。
4. AutoHotkey GUI 完全不可复用，只能参考交互和设置项。
5. 现有密码自动捕获依赖 Windows 控件读取，跨平台实现需重新设计为应用内密码输入和数据库记录。
6. 删除源文件、自动清理嵌套包等高风险操作需要更明确的安全确认和回收站策略。
7. RAR/7z 支持取决于选定后端授权与打包策略。
8. locale/编码自动检测存在误判风险，需要预览、置信度和手动修正机制。
9. 内嵌压缩包扫描可能带来性能和安全风险，需要大小、深度、格式白名单限制。
10. macOS 代码签名、公证和 Linux 多发行版打包会影响发布流程。
